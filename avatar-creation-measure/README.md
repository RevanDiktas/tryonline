# avatar-creation-measure: measurement-only RunPod worker

Photos + height + weight + gender in, body measurements in cm out. No avatar, no textures, no network volume.
Drafted 2026-11-20; street pipeline added 2026-11-25. **Not built, not pushed, not deployed.**

```
front + side photo(s) -> street/   person outline (DeepLabV3) + clothing labels (SegFormer) -> row widths, cloth flags,
                                   bare-limb widths, part locator -> three networks averaged -> optional typed sizes
                                   -> chest / waist / hips / thigh as a tape measures them      ("pipeline": "street")
front photo only      -> model.py  the older silhouette CNN, training-set definitions           ("pipeline": "silhouette_cnn")
height + weight       -> fit.py    SMPL-X body for display only
```

## Street pipeline (2026-11-25)

The same steps as `.local_prototype/measure_ml/measure_street.py`, inference only. Verified on this laptop through the
real handler on four iPhone HEIC photos (192 cm, 85 kg, male): every measurement equal to the runner's (largest gap
0.00 cm at 0.1 cm rounding), without and with typed sizes, decoding HEIC with `sips` and with `pillow-heif`.
About 135 to 145 s for the four photos on one CPU thread; the model step itself is 0.45 s.

| file | copied from (diff against it) | changed |
|---|---|---|
| `street/street_model.py` | GENERATED by `.local_prototype/measure_ml/make_street_worker.py` from the function sources, each block headed by its file: `pipe_profiles.py` (row_runs, resample, limb), `pipe_profiles2.py` (_overlap, front_parts, features), `street_build.py` (rowfeat), `street3.py` (coverfeat, small_pair, pack), `cnn_bodym.py` (meta), `pipe_specialists.py` (split_profile, Enc), `train_street.py` (M, limb_x, cnn_meta, seq_x, make_seq, pred_seq, both_x, make_both, pred_both, tape_prior, to_tape) | module prefixes (`S.`, `SB.`) removed; the tape-prior path is a variable |
| `street/parse_photos.py` | `measure_ml/parse_photos.py` | five lines, listed in `PARSE_PATCHES` in the generator: import path, weight path, no TORCH_HOME default, optional device |
| `street/limbfeat.py` | `measure_ml/limbfeat.py` | nothing |
| `street/pipeline.py` | written by hand after `measure_street.py` (`main`, `apply_typed`) | photo bytes instead of paths; each photo parsed once |
| `weights/street_models.json` | written by the generator | **the one place the model file names live** (version, files, SHA-256) |
| `weights/street_*.pt`, `ansur_tape_prior.npz`, `stage2_sizes.npz` | `measure_ml/`, same names | nothing |

`python make_street_worker.py check` (in `measure_ml`, with venv310) says whether the generated code and the copied
weights still equal their sources. No training code, no BodyM loader, no data builders are in this folder.

**Changing the checkpoints:** `python make_street_worker.py <version> a.pt b.pt c.pt` copies them, removes the ones no
longer listed and rewrites `weights/street_models.json`. Only 'seq' and 'both' street4 networks are accepted.
`stage2_sizes.npz` is fitted on top of one particular network average: **refit it (`stage2_sizes.py`) when the list
changes**, then run the generator and the harness again.

**Weights that are not in this folder** (downloaded by the Dockerfile at build time and checked against a SHA-256; no
network volume):
- DeepLabV3-R101 person segmenter, 233 MB, `download.pytorch.org` (torchvision weights).
- Clothing parser `mattmdjaga/segformer_b2_clothes`, `model.safetensors`, 109 MB, Hugging Face, to
  `/workspace/models/segformer_b2_clothes.safetensors` (`MEASURE_PARSER_WEIGHTS`). **Licence: NVIDIA Source Code
  License for SegFormer, non-commercial; trained on ATR, which has no licence file.** Accepted for pre-seed validation
  only (Revan); it must be replaced before commercial use. The one commercially clean parser tested (MediaPipe
  multiclass) agreed with it on about 9 cloth-edge rows in 10, so it is not a drop-in replacement.
- The street networks are trained on BodyM (CC BY-NC) and the tape anchor on ANSUR II: same pre-seed status.

**Contract changes** (everything else is as before):
- New optional inputs `trouser_waist_cm`, `chest_size_cm`: sizes the shopper types, as a tape reads them.
- With a usable front + side pair the measurements come from the street pipeline and `chest`, `waist`, `hips`,
  `thigh` are in the **tape definition** (`"definition": "tape"`). Without a side photo the older CNN answers in the
  training-set definition (`"definition": "training_set"`): on the same person that chest reads several cm higher,
  so a caller must not mix the two.
- A failed photo check no longer refuses a photo in the street pipeline: it is reported in `checks` (`ok: false`,
  `used: true`) and in `notes`. Only `no_person` and `unreadable` drop a photo (`STREET_BLOCKING` in `handler.py`).
  The networks are trained for arms hanging at the sides, so `arms_not_clear` is not a fault in the street pipeline
  (`STREET_IGNORED`): it is not reported and no shopper is told to move their arms. The value stays in
  `checks.front[i].numbers.arms_clear_pct`.
- New outputs: `pipeline`, `definition`, `between_pairs_sd`, `per_model`, `outfits`, `pairs_used`, and with typed
  sizes `measurements_photo_only` and `typed_sizes`. Front i is paired with side i; the last side is reused.
- HEIC photos are accepted (pillow-heif).

**Not verified without a build:** the image itself (pip resolution: `pillow-heif` needs Pillow 11.1 or newer, so pip
will upgrade the base image's Pillow next to torchvision 0.18); torch 2.3.0 instead of the 2.2.2 used here; the
parser weight download; speed on the worker (`PARSE_THREADS=4` is a guess at the vCPU count); the clothing parser on
the GPU (`MEASURE_PARSER_DEVICE=cuda` exists but has never been run, the default is CPU); DeepLabV3 on the GPU gives
slightly different outlines than on this CPU, so numbers on the endpoint can differ a little from the table above.
Also not run locally: gender neutral through the street pipeline, a pair whose side photo has no person (falls back
to the front-only model), more fronts than sides.

## Output keys and what they measure

**Street pipeline:** `chest`, `waist`, `hips`, `thigh` are re-anchored on tape measurements of 6,068 ANSUR II people
(`to_tape`), so the caveats in the table for those four describe the front-only CNN, not the street pipeline. The
other keys are the same in both.

BodyM computed its labels on SMPL meshes registered to 3D scans. It does not document the individual definitions;
what is written here is inferred from the values (see `.local_prototype/measure_ml/RESULTS.md`).

| our key | BodyM column | what it is, and the caveat |
|---|---|---|
| `chest` | chest | Chest girth. Runs about 3.7 cm above an ANSUR nipple-level chest for the same height and weight, so it is a "largest chest" measure. |
| `waist` | waist | Girth at about navel level, **not** a tailor's natural waist (which sits higher and is smaller). |
| `hips` | hip | Hip girth, 1.6 to 2.6 cm above an ANSUR seat (buttock) girth. |
| `thigh` | thigh | Thigh girth lower on the leg than a tailor's upper-thigh tape: about 5 to 6 cm smaller than a tape at the crotch. |
| `bicep` | bicep | Relaxed upper arm. A flexed bicep reads about 2 cm more. |
| `forearm` | forearm | Relaxed forearm. |
| `wrist`, `calf`, `ankle` | same | Girths; `ankle` is about 2 cm above a minimum-ankle tape. |
| `shoulder_width` | shoulder-breadth | Straight line between shoulder points on the body model, about 36 cm on average. **Not** a tailor's shoulder width and 3.4 cm narrower than bone-to-bone (biacromial). |
| `arm_length` | arm-length | Shoulder point to wrist on the body model, about 50 cm on average. Shorter than a sleeve length; definition unknown. |
| `leg_length` | leg-length | Inside-leg style length, about 78 cm on average. **Not** our older `inseam` key and not floor-to-crotch (that is about 4 cm more), so it is kept under its own name. |
| `torso_length` | shoulder-to-crotch | Top of shoulder to crotch. |
| `height` | (input) | The height the person stated, echoed. The model's own estimate is returned separately as `height_from_photo_cm`. |

Tailoring extras (`extras_keys` lists them): `neck`, `neck_base`, `shoulder_biacromial`, `shoulder_bideltoid`,
`shoulder_length`, `sleeve_outseam`, `sleeve_spine_wrist`, `back_length_waist`, `across_back`, `crotch_height`,
`waist_height`, `cervicale_height`. These come from `weights/ansur_extras.json`: a height + weight + age regression on
ANSUR II tape measurements (typical error 0.8 to 1.9 cm, age missing = 35). The photo does not change them.

Other fields:
- `height_weight_only`: the same keys from height + weight + gender alone, so a caller can show how far the photo moved each one.
- `method`: `front_and_side` or `front_only` (side missing or refused; the reason is in `notes` and `checks.side`).
- `checks.front[i]` / `checks.side[i]`: one entry per photo sent: `ok`, `reason`, `message` (a sentence for the tester), `numbers`.
- Refused front photo: `error` (the message), `reason` (the code), `checks`, and **no** `measurements`.
- `gender: "neutral"`: BodyM has only male and female, so the result is the mean of the two predictions; a note says so.
- `body.tpose_obj_base64`: SMPL-X T-pose, mm, feet on y = 0, 10,475 vertices in SMPL-X order, faces 1-indexed (about 0.8 MB of base64). `null` with a `reason` when height is outside 140 to 210 cm, BMI outside 15 to 45, or the fit does not converge; measurements are still returned. Send `"body": false` to skip it.
- Reasons: `missing_front_url`, `missing_height_cm`, `missing_weight_kg`, `missing_gender`, `bad_input`, `photo_too_large`, `unreadable`, `internal_error`, and the photo gates `no_person`, `landscape`, `several_people`, `too_small`, `cut_off_top`, `cut_off_bottom`, `cut_off_side`, `not_standing`, `arms_not_clear` (front), `not_side_view` (side).

## Before any build (project rule: verify locally first)

```bash
cd avatar-creation-measure
V=../avatar-creation/venv310/bin/python
$V -m py_compile handler.py model.py preprocess.py fit.py street/*.py
$V test_preprocess.py
diff preprocess.py ../.local_prototype/measure_core/preprocess.py && diff fit.py ../.local_prototype/measure_core/fit.py
(cd ../.local_prototype/measure_ml && $OLDPWD/$V make_street_worker.py check)
# street pipeline through the real handler, against a measure_street.py result (fails above 0.1 cm):
$V scripts/local_invoke.py --street --front f1.HEIC f2.HEIC --side s1.HEIC s2.HEIC --height 192 --weight 85 --gender male \
    --expect ../.local_prototype/measure_ml/street_test/revan_heic_avg3.json
# the same with --trouser-waist 89 --chest-size 110 --expect .../revan_heic_avg3_typed.json
# every other case (ping / selftest, front only, front + side, bad input):
$V scripts/local_invoke.py --front <full-body photo> --side <side photo> --refuse <mirror selfie> --height 192 --weight 83 --gender male
```
Expected: ping `ok: true`; the good photo gives 13 measurements + `height` and a body; the selfie is refused with
`arms_not_clear`; missing weight gives `missing_weight_kg`; a refused side photo falls back to `front_only`.

## The front-only model in `weights/measure_cnn.pt`

Installed 2026-11-20: `bodym-v1-30ep-s0` = `.local_prototype/measure_ml/cnn_model_official_s0.pt` (`cnn_bodym.py official 30 0`).
BodyM Test-A 10.4 mm, Test-B 13.7 mm mean error over 14 measurements with front + side. It was trained with bbox
framing, so the sidecar says `"framing": "bbox"` and `model.py` crops to the person before the downscale
(`"native"` = plain downscale, for a `cnn_bodym_v2.py` checkpoint).

To replace it: copy the new `.pt` to `weights/measure_cnn.pt`, set `version`, `sha256` (`shasum -a 256`) and `framing`
in `weights/measure_cnn.json`, run the local harness, commit (the folder's `.gitignore` lets the `.pt` through).
